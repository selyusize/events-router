# Подключить через PSR-14

Сторонняя библиотека или старый код знают только стандартный `Psr\EventDispatcher\EventDispatcherInterface`. Переписывать их под роутер незачем: `Psr14EventDispatcher` — тот же роутер под стандартным интерфейсом.

```php
--8<-- "psr14/psr14.php:example"
```

```text
--8<-- "psr14/psr14.out"
```

## Как объект становится событием

| Что передали в `dispatch()` | Что получает роутер |
| --- | --- |
| объект, реализующий `EventInterface` (например, `Event`) | его же, как есть |
| любой другой объект | `new Event(маппер($object), $object)`: имя даёт маппер из конструктора, сам объект становится payload |
| любой другой объект, а маппера нет | исключение [`UnmappableEvent`](../errors/unmappable-event.md) |

Имя события по имени класса не угадывается. Правило задаёте вы, явно, в одном месте.

## Что гарантирует адаптер

- `dispatch()` возвращает тот же объект, что получил, как требует PSR-14.
- Если объект реализует `StoppableEventInterface`, слушатель может остановить рассылку.
- Ошибки слушателей обрабатываются так же, как в `EventRouter::dispatch()`: тот же обработчик, та же стратегия, тот же лог.

Отчёт о рассылке PSR-14 не возвращает. Если он нужен, вызывайте роутер напрямую.
