# Шаблоны топиков

## Топик

Топик — имя события из сегментов через точку. Аналог URL для событий: путь `/order/42/paid` ↔ топик `order.42.paid`.

```text
shop.order.42.paid
│    │     │  └─ что произошло
│    │     └──── какой именно заказ
│    └────────── о какой сущности
└─────────────── какая система
```

Правила для имени события: непустые сегменты, без пробелов, без символов `*`, `#`, `{`, `}`, регистр важен. Нарушение — [`InvalidEventName`](../errors/invalid-event-name.md).

## Сегменты шаблона

В маршруте пишется не точное имя, а шаблон — он описывает целую группу событий.

| Сегмент | Что совпадает | Пример |
| --- | --- | --- |
| `order` | ровно этот текст, с учётом регистра | `order` |
| `{order_id}` | любой один сегмент, значение попадает в параметр | `42` → `order_id = '42'` |
| `{order_id:\d+}` | один сегмент, целиком подходящий под регулярное выражение | `42`, но не `abc` и не `42abc` |
| `*` | любой один сегмент | `42`, `abc` |
| `#` | **ноль** или больше любых сегментов | ничего, `42`, `42.payment.failed` |

```php
--8<-- "topics/matching.php:example"
```

```text
--8<-- "topics/matching.out"
```

## Параметры

| Правило | Пример |
| --- | --- |
| имя — snake_case: строчные латинские буквы, цифры и `_`, начинается с буквы | `{order_id}`, `{v2}`; не `{orderId}`, не `{_id}` |
| ограничение — regex после двоеточия, совпадает с сегментом **целиком**, `^` и `$` не нужны | `{order_id:\d+}`, `{code:\d{3}}` |
| Unicode в ограничении поддерживается | `{name:\p{L}+}` |
| один параметр — один раз на шаблон | `user.{id}.order.{id}` — ошибка |
| пустой сегмент не совпадает | `order..paid` не подходит под `order.{order_id}.paid` |

Альтернатива в ограничении тоже работает: `{status:paid|cancelled}`.

Значение параметра — строка. Слушатель получает её через `$event->getAttribute('order_id')`.

Литеральные сегменты библиотека не ограничивает: события Bitrix называются `OnAfterUserAdd`. Для своих событий пишите snake_case: `order.unpaid_reminder`.

## `*` и `#`

| Шаблон | Совпадает | Не совпадает |
| --- | --- | --- |
| `order.*.cancelled` | `order.42.cancelled` | `order.cancelled`, `order.42.items.cancelled` |
| `order.#` | `order`, `order.created`, `order.42.payment.failed` | `shop.order` |
| `order.#.failed` | `order.failed`, `order.42.payment.failed` | `order.42.paid` |
| `#` | любое событие | — |

`#` работает как в AMQP: может стоять в любом месте и совпадать с нулём сегментов.

## Ограничения {#limits}

Параметр, `*` и `#` занимают **весь сегмент**. `order-{order_id}` и `ord*` писать нельзя. Сегмент, который нужно разобрать, ловится параметром с regex: `{order_ref:order-\d+}`.

Ошибка в шаблоне видна сразу при объявлении маршрута, а не когда придёт событие:

```php
--8<-- "topics/invalid-pattern.php:example"
```

```text
--8<-- "topics/invalid-pattern.out"
```

Все варианты — на странице [`InvalidTopicPattern`](../errors/invalid-topic-pattern.md).
