# Маршруты

Маршруты лежат в отдельном файле. Файл возвращает функцию, которая получает роутер, — так же, как `routes.php` в Slim.

```php
--8<-- "routes/events.php:example"
```

Итоговый список маршрутов с полными шаблонами и middleware:

```php
--8<-- "routes/dump-routes.php:example"
```

```text
--8<-- "routes/dump-routes.out"
```

## Методы

| Метод | Где есть | Что делает |
| --- | --- | --- |
| `listen(string $pattern, string $listener)` | роутер, группа | вешает **одного** слушателя на шаблон, возвращает маршрут |
| `group(string $prefix, callable $routes)` | роутер, группа | группа с общим префиксом и middleware, возвращает группу |
| `add($middleware)` | роутер, группа, маршрут | добавляет middleware |
| `setPrefix(string $prefix)` | роутер | общий префикс всех топиков, аналог `setBasePath()` |
| `match(string $topic)` | роутер | какие маршруты получат событие, с параметрами |
| `getRoutes()` | роутер | все маршруты с полными шаблонами и middleware |

## `listen()`

```php
$group->listen('{order_id}.paid', Listener\Order\MarkOrderPaid::class);
```

- Первый аргумент — [шаблон топика](topics.md) относительно префикса группы. Внутри группы может быть пустым: `listen('', ...)` слушает само событие с префиксом группы.
- Второй — **ровно один** слушатель: имя класса, реализующего `ListenerInterface`. Ни массивов, ни объектов.
- Несколько слушателей на одно событие — несколько строк `listen()`.

## Порядок вызова

Слушатели одного события вызываются **строго в порядке объявления** маршрутов, сквозь все группы. Приоритетов нет. Чтобы слушатель сработал раньше, объявите его выше.

```php
$order->listen('created', Listener\Order\ReserveStock::class);           // первым
$order->listen('created', Listener\Order\SendConfirmationEmail::class);  // вторым
```

## `group()`

```php
$events->group('order', static function (RouteGroup $group): void {
    // маршруты с префиксом order
})
    ->add(Middleware\EventLog\EventLogger::class);
```

- Префикс соединяется с шаблонами через точку. Группы вкладываются на любую глубину, префиксом может быть параметр: `group('{order_id}', ...)`.
- **Пустой префикс** — `group('', ...)` — группа только ради общих middleware, как `$app->group('', ...)` в Slim.
- **Один префикс в нескольких группах** с разными middleware — можно, маршруты не смешиваются.

## `add()`

Middleware указывается именем класса или готовым объектом. По имени класса объект создаётся [контейнером](../how-to/container.md), когда событие дойдёт до этого middleware.

Порядок выполнения, как в Slim:

1. роутер → внешняя группа → вложенная группа → маршрут;
2. на одном уровне **последний добавленный выполняется первым**.

```php
--8<-- "routes/middleware-order.php:example"
```

```text
--8<-- "routes/middleware-order.out"
```

`add()` на группе можно вызвать после того, как маршруты внутри уже объявлены: middleware применится ко всем маршрутам группы.

Middleware роутера (`$events->add()`) выполняется **один раз на событие** и оборачивает всех слушателей сразу. Подробнее — в [Рассылке](dispatch.md).

## `setPrefix()`

Общий префикс всех топиков. Можно вызвать в любой момент: шаблоны уже объявленных маршрутов пересоберутся. Пустая строка убирает префикс. Если с новым префиксом какой-то шаблон станет некорректным, роутер бросит исключение и останется с прежним префиксом.

## `match()` {#match}

Какие маршруты сработают на событие: **все** подходящие, строго в порядке объявления, у каждого свои параметры.

```php
--8<-- "routes/match.php:example"
```

```text
--8<-- "routes/match.out"
```

## Когда проверяются ошибки

Всё проверяется при объявлении, а не когда придёт событие. Ошибка в файле маршрутов видна при первой загрузке приложения, а стек вызовов указывает на строку с ней.

| Что | Когда | Исключение |
| --- | --- | --- |
| шаблон вместе с префиксами групп и роутера | `listen()`, `setPrefix()` | [`InvalidTopicPattern`](../errors/invalid-topic-pattern.md) |
| класс слушателя существует и реализует `ListenerInterface` | `listen()` | [`InvalidRoute`](../errors/invalid-route.md) |
| класс middleware существует и реализует `MiddlewareInterface` | `add()` | [`InvalidRoute`](../errors/invalid-route.md) |
