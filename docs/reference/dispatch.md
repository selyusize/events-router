# Рассылка и отчёт

`dispatch()` отправляет событие всем подходящим слушателям и возвращает отчёт.

```php
--8<-- "dispatching/dispatch.php:classes"
```

```php
--8<-- "dispatching/dispatch.php:dispatch"
```

```text
--8<-- "dispatching/dispatch.out"
```

## Как проходит рассылка

```text
dispatch(order.42.paid)
  └─ middleware роутера: $events->add(...)          один раз на событие
       └─ для каждого маршрута в порядке объявления:
            middleware групп → middleware маршрута → слушатель
```

1. Роутер находит все подходящие маршруты, как [`match()`](routes.md#match).
2. Событие проходит через **middleware роутера**. Они выполняются один раз на событие, даже если слушателей нет.
3. Каждый слушатель по очереди, в порядке объявления маршрутов:
    - получает **копию** события с параметрами своего маршрута в атрибутах (`order_id = '42'`);
    - проходит через **свои** middleware: групп, затем маршрута.
4. Ошибка слушателя записывается в отчёт, дальше действует [стратегия](#strategies).
5. Если включён `log_dispatch`, рассылка пишется в [лог](../how-to/logging.md).

## Отчёт {#report}

`DispatchReport`:

| Метод | Что возвращает |
| --- | --- |
| `getEvent()` | событие, переданное в `dispatch()` |
| `getListeners()` | `ListenerReport` по каждому подходящему маршруту, в порядке вызова |
| `hasListeners()` | были ли у события слушатели |
| `hasFailures()`, `getFailures()` | упавшие слушатели |

`ListenerReport`:

| Метод | Что возвращает |
| --- | --- |
| `getStatus()` | `ListenerStatusEnum`: см. таблицу ниже |
| `isFailed()` | статус `Failed` |
| `getError()` | исключение для `Failed`, иначе `null` |
| `getRoute()`, `getListener()` | сработавший маршрут и класс его слушателя |
| `getEvent()` | событие, которое получил слушатель, с параметрами маршрута |
| `getDuration()` | время работы слушателя вместе с его middleware, в секундах |

## Статусы

| `ListenerStatusEnum` | Что случилось |
| --- | --- |
| `Handled` | слушатель отработал без исключения |
| `Failed` | исключение в слушателе или его middleware |
| `Skipped` | слушатель не вызван: middleware не вызвал `$next`, рассылку остановили через `StoppableEventInterface` или стратегией `Stop` |

## Стратегии ошибок {#strategies}

Задаются `$events->setErrorStrategy(...)`.

| `ErrorStrategyEnum` | Обработчик ошибок | Остальные слушатели | Исключение из `dispatch()` |
| --- | --- | --- | --- |
| `Continue` — по умолчанию | вызывается | вызываются | нет |
| `Stop` | вызывается | `Skipped` | нет |
| `Throw` | не вызывается | не вызываются | да, исходное |

Исключение из **middleware роутера** и из **самого обработчика ошибок** выходит из `dispatch()` при любой стратегии.

Как этим пользоваться — в рецепте [Обработать ошибки слушателей](../how-to/errors.md).
