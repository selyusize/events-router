# Основные понятия

events-router устроен как HTTP-роутер Slim, только вместо запроса — событие, а вместо Action — слушатель. Все контракты ядра лежат в `Selyusize\EventsRouter\Contract\Core`.

| events-router | Slim / PSR | Что это |
| --- | --- | --- |
| Событие, `EventInterface` | запрос, `ServerRequestInterface` | что произошло: имя-топик, данные, атрибуты |
| Топик | путь URL | имя события из сегментов через точку: `shop.order.42.paid` |
| Слушатель, `ListenerInterface` | Action, `RequestHandlerInterface` | реакция на событие |
| Middleware, `MiddlewareInterface` | PSR-15 `MiddlewareInterface` | обёртка вокруг слушателя; объект с зависимостями через конструктор |
| Маршрут | маршрут | связка «шаблон топика → слушатель + middleware» |

Главное отличие от HTTP: запрос попадает ровно в один Action, а у события может быть **сколько угодно слушателей**.

## Событие {#event}

Событие — это имя, данные (payload) и атрибуты.

```php
--8<-- "concepts/event.php:example"
```

**Имя** — конкретный топик: непустые сегменты через точку. В имени нельзя использовать пробелы и символы шаблонов `*`, `#`, `{`, `}`: они нужны маршрутам, чтобы описывать *группы* событий. Регистр сохраняется. Некорректное имя — исключение [`InvalidEventName`](../errors/invalid-event-name.md).

**Payload** — данные события: массив, DTO или любой объект. Роутер его не трогает.

**Атрибуты** — то, что появилось по пути к слушателю. Параметры шаблона маршрута (`{order_id}` из `order.{order_id}.paid`) и данные, которые добавили middleware.

**Событие неизменяемо**, как PSR-7 запрос. `withAttribute()` возвращает копию, поэтому каждый слушатель получает своё событие со своими параметрами и не может испортить его для остальных. Payload при этом не копируется: если это объект, все копии ссылаются на него.

## Слушатель

Один класс — одна реакция на событие. Метод `handle()` статичный: роутер вызывает `MarkOrderPaid::handle($event)` и объектов не создаёт. Зависимости слушатель берёт сам, например из контейнера.

```php
--8<-- "concepts/listener-and-middleware.php:listener"
```

## Middleware

Middleware оборачивает слушателя: получает событие и замыкание `$next` — продолжение цепочки: следующий middleware или сам слушатель. Вызов — `$next($event)`, как в Laravel. Может сделать что-то до и после, передать дальше изменённое событие или не вызвать `$next`, и тогда событие не дойдёт до слушателя.

```php
--8<-- "concepts/listener-and-middleware.php:middleware"
```

Цепочку из middleware и слушателя собирает роутер. Вот как это выглядит изнутри:

```php
--8<-- "concepts/listener-and-middleware.php:pipeline"
```

Вывод:

```text
--8<-- "concepts/listener-and-middleware.out"
```
