# Топики и шаблоны

## Что такое топик

Топик — имя события из сегментов через точку. Это аналог URL для событий: путь `/order/42/paid` ↔ топик `order.42.paid`.

```text
shop.order.42.paid
│    │     │  └─ что произошло
│    │     └──── какой именно заказ
│    └────────── о какой сущности
└─────────────── какая система
```

Слово взято из брокеров сообщений (в RabbitMQ это routing key). Правила для имени события — в разделе [Основные понятия](concepts.md#event).

## Зачем шаблоны

В маршруте пишется не точное имя, а **шаблон**, который описывает целую группу событий. Так же, как в Slim один маршрут `/order/{order_id}/payment/status` обслуживает все заказы.

| Сегмент шаблона | Что совпадает | Пример |
| --- | --- | --- |
| `order` | ровно этот текст, с учётом регистра | `order` |
| `{order_id}` | любой один сегмент, значение попадает в параметр | `42` → `order_id = '42'` |
| `{order_id:\d+}` | один сегмент, целиком подходящий под регулярное выражение | `42`, но не `abc` и не `42abc` |
| `*` | любой один сегмент | `42`, `abc` |
| `#` | **ноль** или больше любых сегментов | ничего, `42`, `42.payment.failed` |

## Параметры

Значение параметра — строка, роутер кладёт её в атрибуты события. Слушатель получает её через `$event->getAttribute('order_id')`.

- Имя параметра — **snake_case**: строчные латинские буквы, цифры и `_`, начинается с буквы: `{order_id}`, `{user_id}`, `{v2}`. `{orderId}` — ошибка. Литеральные сегменты библиотека не ограничивает (события Bitrix называются `OnAfterUserAdd`), но для своих событий тоже пишите snake_case: `order.unpaid_reminder`.
- Ограничение — регулярное выражение после двоеточия: `{order_id:\d+}`, `{status:paid|cancelled}`, `{code:\d{3}}`. Оно должно совпасть с сегментом **целиком**, `^` и `$` добавлять не нужно. Поддерживается Unicode: `{name:\p{L}+}`.
- Один параметр нельзя использовать в шаблоне дважды.
- Параметр не совпадает с пустым сегментом.

## `*` и `#`

`*` заменяет ровно один сегмент: `order.*.cancelled` ловит `order.42.cancelled`, но не `order.cancelled` и не `order.42.items.cancelled`.

`#` заменяет сколько угодно сегментов, **включая ноль**, как в AMQP:

- `order.#` ловит `order`, `order.created`, `order.42.payment.failed`;
- `order.#.failed` ловит `order.failed` и `order.42.payment.failed`;
- `#` в одиночку ловит любое событие.

## Ограничения {#limits}

Параметр, `*` и `#` занимают **весь сегмент**. В отличие от Slim, `order-{order_id}` и `ord*` писать нельзя. Благодаря этому маршруты можно скомпилировать в быстрое дерево поиска. Сегмент, который нужно разобрать на части, ловится параметром с regex: `{order_ref:order-\d+}`.

Ошибка в шаблоне видна сразу при регистрации маршрута, а не когда придёт событие:
