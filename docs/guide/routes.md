# Маршруты

Маршруты событий описываются в отдельном файле, так же как HTTP-маршруты в Slim. Файл возвращает функцию, которая получает роутер.

```php
--8<-- "routes/events.php:example"
```

Чтобы проверить, что получилось, переберите маршруты:

```php
--8<-- "routes/dump-routes.php:example"
```

```text
--8<-- "routes/dump-routes.out"
```

## Кто получит событие {#who-gets-event}

`match()` показывает, какие маршруты сработают на событие: **все** подходящие, строго в порядке объявления, у каждого свои параметры.

```php
--8<-- "routes/match.php:example"
```

```text
--8<-- "routes/match.out"
```

## `listen()` — один слушатель на шаблон

```php
$group->listen('{order_id}.paid', Listener\Order\MarkOrderPaid::class);
```

- Первый аргумент — [шаблон топика](topics.md) относительно префикса группы.
- Второй — **ровно один** слушатель: имя класса, реализующего `ListenerInterface`. Массивов нет, объектов тоже: слушатели статичные.
- Несколько слушателей на одно событие — несколько строк `listen()`.

Внутри группы шаблон может быть пустым: `$group->listen('', ...)` слушает само событие с префиксом группы.

## Порядок вызова — порядок строк

Слушатели одного события вызываются **строго в порядке объявления** маршрутов в файле, сквозь все группы. Приоритетов нет: чтобы слушатель сработал раньше, объявите его выше.

```php
$order->listen('created', Listener\Order\ReserveStock::class);           // первым
$order->listen('created', Listener\Order\SendConfirmationEmail::class);  // вторым
```

## `group()` — общий префикс и middleware

```php
$events->group('order', static function (RouteGroup $group): void {
    // маршруты с префиксом order
})
    ->add(Middleware\EventLog\EventLogger::class);
```

- Префикс соединяется с шаблонами через точку. Группы можно вкладывать, префиксом может быть и параметр: `group('{order_id}', ...)`.
- **Пустой префикс** `group('', ...)` — группа только ради общих middleware, как `$app->group('', ...)` в Slim.
- **Один префикс можно использовать в нескольких группах** с разными middleware: маршруты не смешиваются.

## `add()` — middleware

`add()` есть у группы и у маршрута. Порядок выполнения, как в Slim:

1. внешняя группа → вложенная группа → маршрут;
2. на одном уровне — **последний добавленный выполняется первым**.

```php
--8<-- "routes/middleware-order.php:example"
```

```text
--8<-- "routes/middleware-order.out"
```

`add()` на группе можно вызвать после того, как маршруты внутри уже объявлены: middleware всё равно применится ко всем маршрутам группы.

## `setPrefix()` — общий префикс всех топиков

Аналог `setBasePath()` в Slim. Можно вызвать в любой момент: шаблоны уже объявленных маршрутов пересоберутся. Пустая строка убирает префикс.

## Когда проверяются ошибки

- **Шаблон** проверяется сразу в `listen()`, вместе с префиксами групп и роутера. Ошибка — [`InvalidTopicPattern`](../errors/invalid-topic-pattern.md) с полным шаблоном в сообщении.
- **Классы слушателей и middleware** при регистрации не загружаются: файл маршрутов выполняется при каждом запуске приложения, и автозагрузка всех классов стоила бы дорого. Класс понадобится, только когда придёт подходящее событие.
