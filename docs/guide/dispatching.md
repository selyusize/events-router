# Рассылка событий

`dispatch()` отправляет событие всем подходящим слушателям и возвращает отчёт.

## Как проходит рассылка

```text
dispatch(order.42.paid)
  └─ middleware роутера: $events->add(...)          один раз на событие
       └─ для каждого маршрута в порядке объявления:
            middleware групп → middleware маршрута → слушатель
```

1. Роутер находит все подходящие маршруты — как [`match()`](routes.md#who-gets-event).
2. Событие проходит через **middleware роутера** (`$events->add()`). Они выполняются один раз на событие, даже если слушателей нет: удобно для трассировки и общего лога.
3. Дальше каждый слушатель по очереди, в порядке объявления маршрутов:
    - получает **копию** события с параметрами своего маршрута в атрибутах (`order_id = '42'`);
    - проходит через **свои** middleware: групп, затем маршрута.

Порядок middleware на каждом уровне — как в Slim: добавленный последним выполняется первым.

## Ошибки не мешают остальным слушателям

Исключение в слушателе или в его middleware по умолчанию не останавливает рассылку. Остальные слушатели отработают, ошибка попадёт в отчёт со статусом `Failed` и в `error_log()`. Свой обработчик, стратегии и остановка рассылки — в разделе [Обработка ошибок](errors.md).

Исключение из **middleware роутера** не относится ни к одному слушателю и выходит из `dispatch()` наружу.

## Отчёт {#report}

`DispatchReport`:

| Метод | Что возвращает |
| --- | --- |
| `getEvent()` | событие, переданное в `dispatch()` |
| `getListeners()` | `ListenerReport` по каждому подходящему маршруту, в порядке вызова |
| `hasListeners()` | были ли у события слушатели |
| `hasFailures()`, `getFailures()` | упавшие слушатели |

`ListenerReport`:

| Метод | Что возвращает |
| --- | --- |
| `getStatus()` | `Handled` — отработал, `Failed` — исключение, `Skipped` — не вызван: middleware не вызвал `$next` или рассылку остановили |
| `getError()` | исключение для `Failed` |
| `getRoute()`, `getListener()` | сработавший маршрут и его слушатель |
| `getEvent()` | событие, которое получил слушатель, с параметрами маршрута |
| `getDuration()` | время работы слушателя вместе с его middleware, в секундах |

## Откуда берутся слушатели и middleware

**Слушатели статичные.** Роутер вызывает `MarkOrderPaid::handle($event)` и объектов не создаёт. Зависимости слушатель берёт сам, например из контейнера.

**Middleware** указываются именем класса или готовым объектом. Объект по имени класса роутер получает при первом событии, которое дошло до этого middleware:

- если роутер создан с PSR-11 контейнером (`EventRouterFactory::create($container)`) и контейнер знает класс — берётся из контейнера;
- иначе создаётся через `new` без аргументов.

Созданный объект переиспользуется для следующих событий. Если класс слушателя или middleware не найден или не реализует нужный интерфейс, слушатель получает статус `Failed` с [`UnresolvableHandler`](../errors/unresolvable-handler.md).
