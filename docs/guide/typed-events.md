# Типизированные события

Payload события может быть любым объектом. Удобный приём — DTO с именованным конструктором, который сам собирает имя события:

--8<-- "typed-events/order-paid.php:dto"

Имя события пишется в одном месте, рядом с данными, а не в каждом вызове `dispatch()`:

--8<-- "typed-events/order-paid.php:dispatch"

Слушатель получает тот же объект через `getPayload()`:

--8<-- "typed-events/order-paid.php:listener"

```text
--8<-- "typed-events/order-paid.out"
```

## Почему так, а не атрибутом

Библиотека не собирает имя события из класса сама: ни атрибутом, ни по имени класса. Именованный конструктор — обычный PHP-код:

- видно, какое событие уйдёт, прямо в месте рассылки;
- нет рефлексии и неявного сопоставления параметров топика со свойствами;
- один способ создать событие — `new Event(...)`.

`EventInterface` объявлен с шаблоном `@template TPayload`, поэтому Psalm и PHPStan знают тип payload у `Event<OrderPaid>`.

## Остановка рассылки

Если DTO реализует PSR-14 `StoppableEventInterface`, слушатель может остановить рассылку — подробнее в [Обработке ошибок](errors.md).
