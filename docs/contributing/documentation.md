# Документация

Сайт собирается из трёх источников, и два из них — сам код.

```text
src/**/*.php (код + PHPDoc) ──► phpDocumentor + saggre/phpdocumentor-markdown ──► docs/api/*.md ─┐
examples/**/*.php (исполняемые примеры, их запускает ExamplesTest) ──► вставляются в страницы ───┤
docs/guide, docs/errors (руководство, пишется руками) ───────────────────────────────────────────┤
                                                                                                 ▼
                                                                    Zensical ──► GitHub Pages
```

Генератор сайта — [Zensical](https://zensical.org) от авторов Material for MkDocs. Конфиг — обычный `mkdocs.yml`. Почему не MkDocs: ветка 1.x больше не развивается, а MkDocs 2.0 несовместим с темами и плагинами 1.x и не поддерживает нужные нам расширения Markdown. Если с Zensical что-то пойдёт не так, тот же `mkdocs.yml` собирается MkDocs 1.6 + Material 9.7 без изменений.

## Команды

```bash
make docs-install   # один раз: Python-окружение в var/venv
make docs           # справочник API + сборка сайта в site/ (--strict: битые ссылки валят сборку)
make docs-serve     # локальный сервер с автообновлением: http://127.0.0.1:8000
```

## PHPDoc: справочник API

Справочник `docs/api/` генерируется на каждую сборку, в git его нет. Всё, что в нём написано, берётся из докблоков публичных классов и методов.

- Первая строка докблока — краткое описание, она попадает в таблицы справочника.
- Ниже — подробное описание в Markdown.
- Пример использования — обычный блок кода ` ```php ` внутри докблока. Тег `@example` не используем: в phpDocumentor он ссылается на файл, а не на код в комментарии.
- Типы пишем максимально точно (`non-empty-string`, `list<Route>`, `class-string<ListenerInterface>`): они попадают в справочник и проверяются Psalm.

## Исполняемые примеры

Пример в руководстве — это файл в `examples/` (в корне репозитория, не в `docs/`: иначе он попал бы на сайт как статический файл). Тест `tests/Docs/ExamplesTest.php` запускает каждый файл отдельным процессом PHP:

- пример должен завершиться с кодом 0;
- если рядом лежит файл `.out` с тем же именем, вывод примера должен с ним совпасть.

На страницу вставляется только нужная часть файла, между маркерами:

```php
<?php

require __DIR__ . '/../../../vendor/autoload.php';   // на странице этого не будет

// --8<-- [start:example]
// ...код, который увидит читатель...
// --8<-- [end:example]
```

```markdown
;--8<-- "getting-started/check-installation.php:example"
```

## Страницы ошибок

Для каждого исключения `src/**/SomethingWrong.php` нужна страница `docs/errors/something-wrong.md`: что произошло, почему, как исправить. Текст исключения содержит ссылку на неё через `Documentation::errorUrl('something-wrong')`. Без страницы `ArchitectureTest` не пройдёт.

## Публикация

`.github/workflows/docs.yml` собирает сайт на каждый pull request и при push в `main` публикует его на GitHub Pages. В настройках репозитория один раз нужно выбрать **Settings → Pages → Source: GitHub Actions**.
