# Основные понятия

events-router устроен как HTTP-роутер Slim. Только вместо запроса — событие, а вместо Action — слушатель. Если держать в голове эту аналогию, остальное складывается само.

| events-router | Slim / PSR | Что это |
| --- | --- | --- |
| событие, `EventInterface` | запрос, `ServerRequestInterface` | что произошло: имя-топик, данные, атрибуты |
| топик | путь URL | имя события из сегментов через точку: `shop.order.42.paid` |
| слушатель, `ListenerInterface` | Action, `RequestHandlerInterface` | реакция на событие |
| middleware, `MiddlewareInterface` | PSR-15 `MiddlewareInterface` | обёртка вокруг слушателя |
| маршрут | маршрут | связка «шаблон топика → слушатель + middleware» |

Главное отличие от HTTP одно: запрос попадает ровно в один Action, а у события может быть **сколько угодно слушателей**. Почти всё, чем роутер событий отличается от HTTP-роутера, следует из этого.

## Событие {#event}

Событие — это имя, данные и атрибуты.

```php
--8<-- "concepts/event.php:example"
```

**Имя** — конкретный топик: что произошло и с чем. Не шаблон, а факт: `shop.order.42.paid`, а не `shop.order.{order_id}.paid`.

**Payload** — данные события: массив, DTO, любой объект. Роутер его не читает и не меняет.

**Атрибуты** — то, что событие собрало по дороге к слушателю: параметры из шаблона маршрута (`order_id` из `order.{order_id}.paid`) и данные, которые добавили middleware.

**Событие неизменяемо**, как PSR-7 запрос. `withAttribute()` возвращает копию. Поэтому каждый слушатель получает своё событие со своими параметрами и не может испортить его для остальных. Payload при этом не копируется: если это объект, все копии смотрят на один и тот же объект.

## Слушатель

Один класс — одна реакция. Метод `handle()` статичный: роутер вызывает `MarkOrderPaid::handle($event)` и объектов не создаёт.

```php
--8<-- "concepts/listener-and-middleware.php:listener"
```

Зависимости слушатель берёт сам, из [контейнера](../how-to/container.md). Почему так — в [Почему так](design.md#static-listeners).

## Middleware

Middleware оборачивает слушателя. Получает событие и замыкание `$next` — продолжение цепочки: следующий middleware или сам слушатель. Может что-то сделать до и после, передать дальше изменённое событие или не вызвать `$next` вовсе — тогда событие до слушателя не дойдёт.

```php
--8<-- "concepts/listener-and-middleware.php:middleware"
```

Цепочку из middleware и слушателя собирает роутер. Изнутри это выглядит так:

```php
--8<-- "concepts/listener-and-middleware.php:pipeline"
```

```text
--8<-- "concepts/listener-and-middleware.out"
```

## Маршрут

Маршрут связывает шаблон топика, одного слушателя и его middleware. Маршруты собираются в группы с общим префиксом и общими middleware, группы — в один файл.

На одно событие может сработать много маршрутов. Роутер найдёт все и вызовет их слушателей по очереди — в том порядке, в каком маршруты записаны в файле. Синтаксис — в [справочнике](../reference/routes.md).
